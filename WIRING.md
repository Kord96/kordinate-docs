# Wiring Projects to the Docs Site

The docs site supports a generic architecture that allows any project to be wired in and displayed automatically.

## Quick Start

```bash
./scripts/wire-project.sh <project-name>
```

This script will:
1. Copy `atlas.json` from the project's augur analysis to the docs site
2. Copy stories and journeys if they exist
3. Create manifest and journey placeholder files
4. Make the project available at:
   - `/dev/<project-name>/` — Journey/guided walkthrough
   - `/dev/<project-name>/atlas/` — Full architecture reference with findings

## How It Works

### Generic Routing

The docs site uses Astro's dynamic routing with `[project]` parameter to create pages that work for any project:

- `/src/pages/[project]/index.astro` — Journey page
- `/src/pages/[project]/atlas/index.astro` — Atlas page
- `/src/pages/[project]/issues/index.astro` — Issues page

When you visit `/dev/fmailai/atlas/`, Astro routes to `[project]/atlas/index.astro` with `project='fmailai'`.

### Data Structure

Each project needs a directory at `src/content/docs/<project-name>/` with:

```
src/content/docs/<project-name>/
├── atlas.json              # Main architecture data (from augur)
├── manifest.json           # Project metadata
├── journeys/               # Journey definitions
│   ├── getting-started.yaml
│   └── ...other journeys
├── stories/                # Analysis stories
│   ├── story1.yaml
│   └── ...more stories
└── storyByNode.json        # Story-to-node mapping
```

### Specific vs Generic Pages

- **Specific pages** (e.g., `/src/pages/logbd/atlas/index.astro`) take precedence over generic ones
- This allows projects to customize their pages if needed while others use the generic template
- The generic template at `[project]/` will handle any new projects automatically

## Project Data Sources

- **atlas.json** — Generated by augur analysis at `<project>/.kord/agents/augur/memory/atlas.json`
- **journeys/** — Story walkthroughs defined in project's journey files
- **stories/** — Analysis results from augur agent investigations
- **storyByNode.json** — Maps story IDs to architecture nodes

## Architecture and Findings

The **Atlas page** serves as the single source of truth for architectural information:
- **Violations & Recommendations** sorted by severity (Critical/High first)
- **Failure Modes** with trigger conditions, impact, and recovery paths
- **Architecture Graph** showing components and their relationships
- **Components** grouped and documented
- **External Dependencies** and their criticality
- **Design Patterns** and domain model

This consolidation eliminates redundant "Issues" pages while providing a more complete, actionable reference.

## Adding a New Project

1. Run the wiring script:
   ```bash
   ./scripts/wire-project.sh new-project
   ```

2. Visit `/dev/new-project/` in your browser

3. (Optional) Customize pages by creating project-specific pages in `/src/pages/new-project/`

## Updating Project Data

To update a project's data after new analysis:

```bash
./scripts/wire-project.sh <project-name>
```

This will re-copy the latest atlas.json and stories from the project.

## Files

- `scripts/wire-project.sh` — Wiring automation script
- `src/pages/[project]/` — Generic page templates
- `src/content/docs/` — Project data directories
